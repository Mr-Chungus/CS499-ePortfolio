About This Portfolio

This ePortfolio was created as part of the CS 499 Computer Science Capstone at Southern New Hampshire University. It demonstrates skills developed throughout the Computer Science program in software design and engineering, algorithms and data structures, databases, and security.

The main artifact in this portfolio is an Animal Shelter Dashboard originally created for CS-340 Client/Server Development. I enhanced the same project in three different areas to show how one application can be improved from several technical perspectives.

Professional Self-Assessment

My experience at SNHU has been overall good and the coursework throughout the Computer Science program has introduced me to a lot of different technologies. One of the biggest things I have taken away from the program is a better understanding of how different parts of a computer system work together. This includes software, databases, hardware, networking, and security. I do not plan to focus my career completely on software development. I would rather stay more on the systems engineering, infrastructure, networking, and backend side of IT. Even with that being the case, understanding how software is built and how it interacts with everything around it will still help me in the roles that I want to pursue.

The program also showed me how many tools and resources are available to developers today. In CS-360 I was introduced to Android development and Android Studio. This showed me how much an existing IDE and framework can make developing an application easier. One thing I learned throughout the program is that I do not have to know how to build every part of something from scratch. Being able to research a problem, understand the tools that already exist, and figure out which tool works best is just as important. There are so many resources available now that with enough time and the drive to figure something out, there are not many problems that cannot at least be approached.

I did not have many opportunities at SNHU to work directly with a team on programming projects, but I have had team experience through coursework at another college. One of the biggest things I learned from that is that communication is paramount when multiple people are working toward the same goal. Without good communication, work can get repeated or different pieces of the project may not work together correctly. Communication is also important when working with stakeholders or clients. You can spend a lot of time making something that works great, but if it does not do what the person actually asked for, then a lot of that work was wasted. Making sure the requirements are understood before starting and continuing to communicate while working on the project can prevent a lot of problems.

My coursework also helped me better understand data structures and algorithms. I learned that there can be several ways to solve the same problem, but how the data is stored and processed can affect how well the solution works. Lists, dictionaries, sets, searching, and sorting all have different uses depending on the problem. In CS-370 I was also introduced to machine learning. I worked with a pendulum program and learned things like what an epoch is and how changing the number of epochs can affect both learning accuracy and how long training takes. This helped me understand more about what is actually happening when a machine learning model is training instead of just looking at it as a black box that gives an answer.

Software engineering and databases were also a big part of the program. In CS-340 I learned how an application client can interact with a database. I worked with MongoDB and learned how an application can create, read, update, and delete information from a database. I also learned the difference between relational and non-relational databases and why one may work better than another depending on the application. Another big thing I learned is that just because a program works does not mean it is designed well. How the code is organized, how errors are handled, how input is validated, and how the database is designed can make a huge difference when it comes time to troubleshoot or modify the application later.

Security is another area that became more important to me throughout the program. Security should not just be something added at the end after the application is already finished. It needs to be thought about while the system is being designed. Input validation is one example because bad or unexpected input can crash an application or cause security problems like injection attacks. Things like protecting credentials, limiting access, handling errors correctly, and thinking about how somebody could misuse the system are also important. Even though I want to work more in systems engineering, these concepts still matter because systems engineers are responsible for a lot of the systems and services that applications depend on.

For my ePortfolio, I used a project from my Client/Server Development course, CS-340, as the artifact for all three enhancement areas. I originally created the project in August of last year. It is an animal shelter dashboard that uses Python and MongoDB to display, filter, and manage animal data. At first I picked one artifact for all three enhancements because I thought it would make the capstone easier. I later learned that making all three enhancements work together actually created its own problems because changing one part of the application could affect another part.

The three enhancements show different parts of the same application. The software design and engineering enhancement focused on reorganizing the application so it would be easier to maintain, troubleshoot, and modify. The algorithms and data structures enhancement added a ranking system that evaluates animals instead of only giving a yes or no answer. The database enhancement improved validation, database safety, error handling, and how records are created, updated, and deleted. Together these enhancements show that the same application can be improved in several different areas instead of just adding more features.

Overall, completing the Computer Science program and building the ePortfolio helped me better understand what areas of computer science I enjoy the most. I am more interested in systems engineering, infrastructure, networking, and backend work than front-end development. At the same time, having experience with programming, databases, algorithms, machine learning, and security gives me a better understanding of the applications and services running on those systems. I think this will make me more useful in an IT or systems engineering role because I can understand more than one part of the environment and how everything works together.

Artifact Enhancements

01

Software Design & Engineering

The original notebook-based application was reorganized into separate modules for configuration, database access, validation, dashboard layout, callbacks, and application startup. This improved maintainability, troubleshooting, code reuse, and separation of concerns.

Skills: Python, modular design, configuration management, logging, validation, testing

02

Algorithms & Data Structures

The original yes-or-no rescue filtering was expanded with a weighted suitability ranking algorithm. Animals are evaluated by breed, age, sex, and location data and then ranked from strongest to weakest match.

Skills: algorithms, dictionaries, sets, lists, sorting, scoring, design trade-offs

03

Databases

The MongoDB layer was improved with validation, safer create/update/delete behavior, better exception handling, indexing, auditing, and improved query functionality. These changes focused on reliability, security, and data integrity.

Skills: MongoDB, CRUD, indexing, validation, auditing, defensive programming

Code Review
